# Registry

Machine-readable, artifact-derived descriptions of what this repository contains and what it
claims. Nothing here is a source of truth: every value is recomputed from the file it describes by
`uv run python scripts/validate.py`, and a value that stops matching fails the run.

| File | What it is | Verified by |
|---|---|---|
| `studies.yaml` | the study model: Study 001 frozen, Study 002 in progress, and every headline result with the artifact that backs it | `studies_registry_matches_config`, `study_002_has_no_results` |
| `datasets.yaml` | every corpus under `data/`: record counts, splits, hash algorithm, freeze membership, contamination status, and a `file:line` anchor for each documentary claim | `dataset_registry_counts_match`, `dataset_registry_hashes_match`, `dataset_registry_evidence_resolves` |
| `benchmarks.yaml` | what is and is not a benchmark, with probe/persona/category counts for PMB and an explicit `is_benchmark: false` for the training-persona corpora | `benchmark_registry_counts_match`, `no_result_from_non_benchmark` |
| `claims.jsonl` | the claims matrix: one line per public claim, with a machine-evaluable check | `scripts/validate.py`'s `claims` section |
| `papers.jsonl` | the paper ledger: every paper this repository cites or whose method it implements, with how it was verified and what it does and does not support | `scripts/validate.py`'s `papers` section |

`results/registry.jsonl` is the same idea applied to evaluated runs. It lives next to the results it
indexes and is generated by `scripts/build_result_registry.py`.

## `claims.jsonl` schema

One JSON object per line:

```json
{
  "id":     "readme-pmb-probe-count",
  "claim":  "688 adversarial probes",
  "where":  "README.md:43",
  "artifact": "data/benchmarks/pmb_v0_full/probes.jsonl",
  "check":  {"type": "count_lines", "glob": "data/benchmarks/pmb_v0_full/probes.jsonl", "equals": 688},
  "status": "verified"
}
```

- **`id`** — stable slug, unique. Renaming one is a change to the audit record, not a refactor.
- **`claim`** — the sentence being asserted, quoted or paraphrased from the document in `where`.
- **`where`** — `file:line` of the claim. The file must exist; the line is a locator for a human
  and is not itself checked, because it moves whenever an unrelated paragraph is added above it.
- **`artifact`** — the file that backs the claim, or `null` when none exists (always `null` for
  `manual`).
- **`check`** — a machine-evaluable spec, one of the types below.
- **`status`** — `verified`, `manual`, or `acknowledged_drift`.
- **`resolution`** — required when `status` is `acknowledged_drift`.

### Check types

```json
{"type": "file_exists", "path": "uv.lock", "equals": true}
```
`equals` defaults to `true`; use `false` for a claim that something is absent.

```json
{"type": "json_field", "path": "results/v0.1/D_memory/metrics.json",
 "field": "metrics.pra_lenient", "equals": 0.1513157894736842,
 "decimals": 2, "quoted": 15.13}
```
Loads JSON, or YAML when the path ends in `.yaml`/`.yml`, and walks the dotted field. The
pseudo-field `"len"` yields the length of a top-level array or object. `tolerance` (default 1e-12)
is an absolute float comparison. With `decimals` and `quoted`, the value is *also* checked as a
percentage: `round(value * 100, decimals) == quoted`. That is how a document saying `15.13%` is
compared to an artifact holding `0.1513157894736842`, without either side being rounded by hand.

```json
{"type": "count_lines", "glob": "data/benchmarks/pmb_v0_full/probes.jsonl", "equals": 688}
```
Counts non-empty lines across the glob's matches.

```json
{"type": "computed", "expr": "split_counts('data/sft/v1') == (2232, 248)"}
```
Evaluates an expression in a deliberately tiny language: numeric and string literals, tuples, lists,
`+ - * / // %`, `== != < <= > >=`, `and or not`, and calls to the named helpers in
`scripts/validate.py`. There is no attribute access, no subscripting, no comprehension, no `import`,
and no builtin — the expression can only observe this repository. Helpers take literal arguments
only. An expression that already returns a boolean is used as-is; otherwise add `"equals"` (and
optionally `"tolerance"`).

```json
{"type": "cross_doc", "equals": 15.13,
 "sources": [{"path": "README.md", "pattern": "…([\\d.]+)%"},
             {"path": "docs/STUDIES.md", "pattern": "…([\\d.]+)%"}]}
```
One capture group per source; every captured number must equal `equals`. This is the check used when
the *same* metric is quoted in more than one document.

```json
{"type": "manual", "reason": "no llama-bench artifact is committed, so this cannot be recomputed"}
```
Not machine-checkable. Always reported in the run summary, never silently passed.

### Statuses

- **`verified`** — the check must pass, and a mismatch fails the run.
- **`manual`** — `check.type` must be `manual` and must carry a `reason`. Use this only when the
  claim genuinely cannot be evaluated from committed files: no artifact backs it (quantization
  figures), it needs the network (Hub state), it needs the GPU stack (training-time step counts),
  or the artifact it would need was deliberately not committed (superseded intermediate runs).
  "It is hard to check" is not a reason; "the evidence does not exist in this repository" is.
- **`acknowledged_drift`** — used only for a claim whose quoting document is a Study 001 frozen
  artifact that the audit rules forbid editing. The entry carries a `resolution` naming the
  superseding record, and the validator prints it on every run. It is a watchlist, not a
  suppression: an entry whose claim starts holding is reported as resolved so it can be promoted.

## Adding or changing a claim

1. Add the claim to `registry/claims.jsonl` with the narrowest check that actually tests it.
2. Run `uv run python scripts/validate.py`. If your check fails, fix the check or the document —
   not the expected value. A silently widened tolerance is how a claims matrix stops meaning
   anything.
3. If the claim is about a number a document states, and the document is frozen, the change is an
   errata entry (`reports/ERRATA.md`) against the frozen artifact, or a Study 002 result. See
   `docs/AUDIT.md` and `docs/STUDIES.md`.

## `papers.jsonl` schema

One JSON object per line. A paper earns an entry when a document cites it or when code implements
a method it is the source of. The ledger records provenance, not endorsement: what was checked,
how, and how far the citation reaches.

```json
{
  "id":         "arxiv-2503.01747",
  "identifier": {"arxiv": "2503.01747"},
  "title":      "Position: Don't use the CLT in LLM evals with fewer than a few hundred datapoints",
  "authors":    "Bowyer, Aitchison, Ivanova",
  "year":       2025,
  "venue":      "arXiv",
  "verified":   {"how": "pwc paper info 2503.01747", "on": "2026-11-11", "read": "abstract only"},
  "found_by":   "ml-side-notes hook proposed it; checked by hand against the abstract",
  "role":       "caveat",
  "supports":   "CLT-based error bars on small LLM benchmarks underestimate uncertainty.",
  "does_not_support": "Anything about bootstrap intervals, including this repository's.",
  "cited_in":   ["reports/ERRATA.md:<line>"],
  "planned_for": ["E36", "E39"],
  "used_by":    []
}
```

- **`identifier`** — `arxiv`, `doi` and/or `jstor`. A `cited_in` file must contain one of them.
- **`verified`** — `how` (the command or record used), `on` (date), `read` (how much of the work
  was actually read: `abstract only`, `bibliographic record only`, `full text`). A citation may
  claim no more than `read` covers.
- **`role`** — `caveat` (supports reading a result cautiously), `method-source` (the origin of a
  method implemented here) or `background`.
- **`supports` / `does_not_support`** — both required. The second is the guard: it names the
  nearest claim the paper would be mistaken for supporting.
- **`cited_in`** — `file:line` of each citation; the line is a locator, the file is checked.
- **`planned_for`** — drafts that will cite it (for example erratum ids) before they are written.
- **`used_by`** — `path::function` for each implementation; the `def` must exist. Required for
  `method-source`.

The validator fails when an entry lacks a required field, has an unknown role, an empty
`supports`/`does_not_support`, no `cited_in`/`planned_for`/`used_by` at all, a `cited_in` file
without the identifier, or a `used_by` function that does not exist; and when any `arXiv NNNN.NNNNN`
cited in `README.md`, `reports/ERRATA.md`, `docs/**/*.md` or `registry/*.yaml` has no entry.
